# 大模型训练推理总览

大模型训练层——大模型训练全流程框架

大模型训练的全流程框架，是一个先通过预训练和监督微调构建模型的基础能力，再通过人类反馈强化学习完成关键价值对齐的系统性工程。

大模型训练层——大模型训练阶段的资源消耗

大模型训练阶段消耗的资源主要集中在预训练阶段，需要数千至上万块GPU并行运算、处理千亿级至万亿级Token数据、耗时数周至数月，占总算力消耗的90-99%。

![img](C:\Users\will\Downloads\assets\b7ca56fd3453a965e0f1c45ff93645b3.png)

大模型训练需要海量算力、存储和数据资源，其中预训练阶段往往消耗了总算力的90-99%及绝大部分时间：要下载并处理数TB级文本语料，调度数千乃至上万块GPU持续数周至数月完成基础参数学习；而微调阶段因仅需在已有模型上进行少量梯度更新与标注评估，其算力消耗仅占1-10%,典型周期也缩短至几日或一周左右。

以GPT-3为例，其在6,000块A100 GPU上投入约34天完成预训练，后续微调阶段又耗时8天，总计42天；LLaMA系列则更具代表性：LLaMA-1在约2,028块GPU上用90天训练1-1.4万亿Token,LLaMA-2则在42天内完成2万亿Token的预训练，LLaMA-3动用约16,384块H100 GPU在54天内训练15万亿Token。

大模型推理层——大模型推理阶段流程框架

大模型推理的流程为输入文本先经分词和嵌入层映射为向量，通过多层Transformer 的自注意力计算并结合KV缓存提升性能，再在词汇概率输出层生成并通过后处理拼接成完整文本。

大模型推理层——大模型推理阶段主流参数

大模型推理后处理技术是通过温度采样、Top-k/Top-p裁剪与贪心选择对输出概率分布进行调控，为了在生成多样性、语义连贯性与输出稳定性之间实现最佳平衡。

![img](C:\Users\will\Downloads\assets\48541489569e362159ce231dc41fcf37.png)

大模型推理层——大模型推理核心阶段

大模型推理分为并行Prefill与增量Decode两阶段，分别依托模型并行与批量吞吐、以及KV缓存与注意力优化，实现了高效低延迟的推理流水线。

![img](C:\Users\will\Downloads\assets\7810897f5bfe501b9e5c8d5f12735a5d.png)

大模型推理阶段Prefill和Decode是两大核心阶段，Prefill阶段负责一次性并行处理所有输入token,通过多层Transformer计算并构建KV缓存，以“速读”形式完整理解上下文；Decode阶段则采用自回归方式逐token生成输出，每次仅做增量推理并依托前序缓存，类似“逐字成文”地写出答案。

根据两阶段的资源与计算特性，需分别制定优化策略：对Prefill阶段，应强化GPU计算吞吐——通过批量合并多个请求提升并行度，并运用模型并行将Transformer层切分至多块GPU;对Decode阶段，则侧重内存与延迟优化——利用KV缓存避免重复计算，并引入Flash Attention、多查询注意力等技术以降低内存带宽占用和加速串行推理。

大模型推理层——大模型推理PD分离技术

PD分离是将一次性上下文预填充与逐token串行解码解耦的策略，实现了GPU算力的精准调度与高效利用，显著降低了响应延迟并提升了整体推理吞吐率。

![img](C:\Users\will\Downloads\assets\82fa1dcfb6ff25e69e059cae284ed600.png)

传统推理流程将Prefill阶段与Decode阶段一体化处理，导致Decode无法发挥GPU的并行计算能力，其耗时占总推理时间超过99%,既造成响应延迟极高，也让海量算力资源在生成过程中严重浪费。

而PD分离策略将Prefill与Decode解耦后，能够为两阶段分别应用最优调度：Prefill可批量合并请求、最大化GPU并行吞吐，显著缩短首次响应时间(TTFT);Decode则依托KV缓存、内存带宽优化及专用流水线，大幅提升后续生成速率(TPOT)。这一分离不仅显著提升整体推理性能和资源利用率，还为独立的分阶段优化与系统级智能调度奠定了坚实基础。

这套流程不是由一篇论文一次性提出，而是在生成式预训练、人类反馈学习、指令微调和偏好优化等工作中逐步形成。

### 1. Pre-training：先训练通用 Base Model

Pre-training 的目标，是先利用大规模无标注文本训练通用 Base Model。对于现代 Decoder-only LLM，最典型的训练目标是 **Next Token Prediction**。

下面以 GPT-1 作为生成式预训练路线的代表性起点。

#### 代表论文：GPT-1

**Improving Language Understanding by Generative Pre-Training（2018）**

-   论文：https://cdn.openai.com/research-covers/language-unsupervised/language_understanding_paper.pdf
-   OpenAI 技术介绍：https://openai.com/index/language-unsupervised/

GPT-1 将 Transformer 与生成式预训练结合，形成影响深远的两阶段路线：

``` text
大量无标注文本
      ↓
Generative Pre-training
      ↓
Pre-trained Model
      ↓
Supervised Fine-tuning
      ↓
Downstream Tasks
```

其核心思想是：**先利用大量无标注文本学习通用语言能力，再利用有标注数据进行任务适配。**

对于现代 Decoder-only LLM，Pre-training 最典型的训练目标是 **Next Token Prediction**。

#### GPT-1：用生成式预训练建立现代 LLM 的两阶段起点

##### 来源

- Alec Radford、Karthik Narasimhan、Tim Salimans、Ilya Sutskever，*Improving Language Understanding by Generative Pre-Training*（2018）：[论文 PDF](https://cdn.openai.com/research-covers/language-unsupervised/language_understanding_paper.pdf)
- OpenAI，*Improving language understanding with unsupervised learning*（2018-06-11）：[技术介绍](https://openai.com/index/language-unsupervised/)

> **模型：** GPT-1   **模型厂家：** OpenAI   **论文名称：** Improving Language Understanding by Generative Pre-Training   **作者：** Alec Radford、Karthik Narasimhan、Tim Salimans、Ilya Sutskever，2018   **发布时间：** 2018 年 6 月 11 日   **原文：** [论文 PDF](https://cdn.openai.com/research-covers/language-unsupervised/language_understanding_paper.pdf)｜[OpenAI 技术介绍](https://openai.com/index/language-unsupervised/)

##### 核心观点

GPT-1 将 Transformer 与生成式语言模型预训练结合，确立了一条影响深远的两阶段路线：

```text
大量无标注文本
      ↓
Generative Pre-training
      ↓
Pre-trained Model
      ↓
Supervised Fine-tuning
      ↓
Downstream Tasks
```

它的核心思想是：**先利用大量无标注文本学习通用语言能力，再利用少量有标注数据适配具体任务。** 这改变了当时“每个 NLP 任务从头训练一个专用模型”的主流做法：同一个预训练 Transformer 骨干可以迁移到文本蕴含、问答、语义相似度、分类与常识推理等不同任务。

###### 1. 生成式预训练的本质是 Next Token Prediction

GPT-1 在无标注文本上训练一个从左到右的 Transformer Decoder。给定前文 token，模型最大化下一个 token 的条件概率：

$$
\mathcal{L}_1(U)=\sum_i \log P(u_i\mid u_{i-k},\ldots,u_{i-1};\Theta)
$$

这就是今天 Decoder-only LLM 最典型的 **Next Token Prediction（下一个 token 预测）** 目标。训练信号不来自人工标签，而直接来自原始文本本身：文本中的每个位置都提供“根据此前上下文预测当前位置”的学习任务。

因此，预训练并不是让模型背诵固定问答，而是迫使它在预测过程中学习词法、句法、语义、长距离依赖及部分世界知识。GPT-1 使用的是多层 Transformer Decoder、masked multi-head self-attention、位置嵌入和 token 嵌入；“masked”保证当前位置不能看到未来 token，从而维持自回归预测的因果方向。

###### 2. 微调把通用语言模型变成任务模型

在下游任务上，GPT-1 将输入送入预训练模型，取最终 Transformer block 的表示，再添加一个很小的线性输出层进行分类：

$$
P(y\mid x_1,\ldots,x_m)=\operatorname{softmax}(h_m^lW_y)
$$

预训练参数与输出层共同在标注数据上微调。论文还发现，将语言模型目标作为辅助项加入微调，有助于泛化并加快收敛；但核心迁移机制仍是“先自回归预训练，再用监督信号调整”。

![Figure 1：GPT-1 的 Transformer 骨干与任务微调输入形式](C:\Users\will\Downloads\assets\OpenAI-GPT-1-2018-v3.0-figure-1.png)

*Figure 1：左侧为 GPT-1 使用的 Transformer Decoder 与语言模型/任务分类目标；右侧将分类、文本蕴含、相似度和多选题统一改写为 token 序列，再接同一预训练模型与线性输出层。来源：[论文第 4 页](https://cdn.openai.com/research-covers/language-unsupervised/language_understanding_paper.pdf#page=4)。*

图中最关键的设计不是给每个任务重做一套网络，而是 **input transformation（输入改写）**：例如将“前提 + 分隔符 + 假设”拼成一个连续序列处理文本蕴含；将“上下文 + 问题 + 候选答案”分别送入同一模型处理多选任务。这样，任务差异主要落在输入格式与一个轻量输出头上，而预训练骨干保持一致。

###### 3. GPT-1 的历史意义：验证“预训练越好，迁移越强”

OpenAI 的技术介绍指出，该模型先以 language modeling 作为无监督训练信号在大规模文本上训练，再在更小的监督数据集上微调。论文报告，在研究的 12 项任务中有 9 项刷新当时结果；其中 Stories Cloze Test、RACE 与 MultiNLI 的绝对提升分别为 8.9、5.7 与 1.5 个百分点。

这让一个后来成为大模型主线的判断首次得到系统验证：**只要预训练语言模型获得更强的文本建模能力，同一个核心模型就可以通过少量任务适配改善多类下游能力。** OpenAI 当时也观察到，语言模型性能提升与下游任务提升具有较强相关性。

###### 4. GPT-1 不等于今天的“只预训练就能对话”的 LLM

GPT-1 的训练范式与现代 Decoder-only LLM 的预训练目标相通，但它的使用方式仍以有监督任务微调为中心：论文模型规模、数据规模和上下文长度都远小于后来的 GPT 系列；它使用的 BooksCorpus 约 7,000 本书，官方说明预训练约使用 8 张 P600 GPU 训练一个月。

因此，不能把 GPT-1 的结果直接等同于当代 ChatGPT、指令微调或 RLHF 的能力。它奠定的是更基础的路线：用自回归生成式建模从无标注文本取得通用表征，再把这些表征迁移到具体任务。

##### 带来的收益

- **突破标注数据瓶颈**：无标注文本远多于高质量任务标签；预训练让有限标注更多用于“适配”，而不是从零学习语言。
- **统一多类 NLP 任务**：相同 Transformer 骨干通过输入改写和少量输出层调整，可覆盖分类、蕴含、相似度、阅读理解与常识推理。
- **奠定 Decoder-only LLM 的预训练目标**：GPT-1 的左到右语言模型目标，就是现代自回归大模型常说的 Next Token Prediction。
- **开启可扩展的能力路线**：GPT-1 已指出增加数据与算力存在继续提升的空间；后续 GPT 系列将这一思路扩展到更大的模型、数据和更丰富的后训练方法。

一句话：**GPT-1 证明了一个 Transformer 可以先靠 Next Token Prediction 从无标注文本中学会通用语言能力，再经监督微调服务多种任务——这是现代生成式大模型路线的关键起点。**

### 2. Post-training：SFT → Human Preference → Reward Model → RLHF/PPO

Pre-training 得到 Base Model 后，还需要通过 Post-training 将通用的文本生成能力进一步转化为指令遵循与偏好对齐能力。InstructGPT 是这条经典路线的代表性工作。

#### 代表论文：InstructGPT

**Training Language Models to Follow Instructions with Human
Feedback（2022）**

-   论文：https://arxiv.org/abs/2203.02155
-   OpenAI 官方介绍：https://openai.com/index/instruction-following/

InstructGPT 第一阶段收集人工 demonstrations，并使用这些示例对预训练 GPT-3 进行监督微调。

> **SFT：通过高质量"指令---回答"数据，让 Base Model 学习指令遵循和期望的回答方式。**


#### 来源

- Long Ouyang、Jeff Wu、Xu Jiang、Diogo Almeida 等，*Training Language Models to Follow Instructions with Human Feedback*（2022）：[arXiv](https://arxiv.org/abs/2203.02155)｜[PDF](https://arxiv.org/pdf/2203.02155)
- OpenAI，*Aligning language models to follow instructions*（2022-01-27）：[官方介绍](https://openai.com/index/instruction-following/)

> **模型：** InstructGPT　 **模型厂家：** OpenAI　 **论文 ID：** arXiv:2203.02155　 **论文名称：** Training Language Models to Follow Instructions with Human Feedback　 **作者：** Long Ouyang、Jeff Wu、Xu Jiang、Diogo Almeida、Carroll L. Wainwright、Pamela Mishkin 等，2022　 **发布时间：** 2022 年 3 月 4 日（arXiv 首次提交）　 **原文：** [arXiv](https://arxiv.org/abs/2203.02155)｜[PDF](https://arxiv.org/pdf/2203.02155)

#### 核心观点

InstructGPT 最具影响力的贡献之一，是将大语言模型的后训练（Post-training）系统化为一条清晰的流水线：**SFT 提供示范，Human Preference 定义相对质量，Reward Model 将偏好转成奖励，RLHF/PPO 再把奖励优化回生成策略。**

```text
Pre-trained LLM
      ↓
Step 1：SFT（训练数据：Human Demonstrations）
      ↓
SFT Model
      ↓
Step 2：Reward Model（训练数据：Human Rankings）
      ↓
Step 3：RLHF / PPO
      ↓
Aligned Model（InstructGPT）
```

这里必须区分“步骤”和“数据”：Human Demonstrations 是 Step 1 的输入，不是在 SFT 之后才出现；Human Rankings 同样是 Step 2 训练 Reward Model 的输入。这一组织方式把“如何回答”“哪种回答更好”“如何让模型稳定偏向更好的回答”拆成三个可独立改进的环节。

##### 1. SFT：用高质量指令—回答示例建立行为起点

第一阶段由标注者针对 prompt 写出期望回答，再用这些 demonstrations 对预训练 GPT-3 进行监督微调。

> **SFT：通过高质量“指令—回答”数据，让 Base Model 学习指令遵循和期望的回答方式。**

SFT 解决的是“模型应如何开始回答”的问题。预训练模型擅长预测下一个 token，却未必自然遵循用户指令；示范数据让它从通用文本续写转向更符合任务意图的初始策略。它也是后续采样候选回答、收集偏好和进行强化学习的可靠起点。

##### 2. Human Preference → Reward Model：把主观判断变成优化信号

第二阶段对同一个 prompt 采样多个模型输出，由标注者排序。排序不是要求人写唯一标准答案，而是直接回答“在这些具体候选中，哪个更好”。

Reward Model（RM）学习为 \((prompt, answer)\) 输出标量 \(r\)：被人类偏好的回答应获得更高分。于是一次人工排序被转换为可以批量评估新输出的奖励函数。

##### 3. RLHF / PPO：利用 RM 奖励更新策略

第三阶段让 SFT policy 为新 prompt 生成回答，RM 打分，再使用 PPO 更新 policy，使其更倾向于产生高奖励回答。论文的原始 Figure 2 将三段式管线完整可视化：

![Figure 2：InstructGPT 的 SFT、偏好排序/RM 与 PPO 三阶段后训练](C:\Users\will\Downloads\assets\arXiv-2203.02155-v6.0-figure-2.png)

*Figure 2（论文第 3 页）：左侧以 demonstrations 训练 SFT；中间由标注者排序多个候选、训练 RM；右侧用 RM 的奖励经 PPO 更新策略。来源：[论文 PDF，第 3 页](https://arxiv.org/pdf/2203.02155#page=3)。*

这就是后续经常被概括为 `SFT → Human Preference → Reward Model → RLHF/PPO` 的经典 LLM Post-training Pipeline。它并非让模型凭空获得新知识；更准确地说，是将预训练已学到的能力引导为更容易被用户触发、更符合标注偏好的行为。

#### 带来的收益

- **把“会说话”推进到“更会按要求做事”：** SFT 定义期望输出形态，偏好数据进一步表达 helpful、honest、harmless 等难以用单一自动指标刻画的目标。
- **将昂贵的人类判断规模化：** 人类只需比较少量候选，RM 就可为大量新输出提供奖励，PPO 再将这种偏好写回模型参数。
- **确立了可复用的后训练分工：** SFT、偏好数据、RM 和 RL 各自承担不同职责，后续系统可以分别替换数据、奖励建模或优化算法。
- **在论文评测中带来明显偏好收益：** 标注者更偏好 1.3B 参数的 InstructGPT 输出而非 175B GPT-3 输出；这是该论文特定提示分布和标注偏好下的结果，不代表参数规模不再重要。
- **保留关键边界：** RM 学到的是特定标注者群体及其指导下的偏好，不能自动等同于普遍人类价值；RLHF 也可能对某些通用 NLP 任务产生性能回退，论文以 PPO-ptx 缓解该问题。

一句话：**InstructGPT 将 SFT 提供的“期望做法”、人类排序给出的“相对好坏”、Reward Model 形成的“可计算奖励”与 PPO 的“策略优化”连成了现代大模型 Post-training 的经典管线。**

### 3. DPO：直接偏好优化

#### 代表论文

**Direct Preference Optimization: Your Language Model is Secretly a Reward Model（2023）**

论文：https://arxiv.org/abs/2305.18290

经典 RLHF：

``` text
SFT Model
    ↓
Preference Data
    ↓
Reward Model
    ↓
PPO
    ↓
Aligned Model
```

DPO：

``` text
SFT Model
    ↓
Chosen / Rejected
Preference Pairs
    ↓
DPO
    ↓
Aligned Model
```


#### 来源

- Rafael Rafailov、Archit Sharma、Eric Mitchell、Stefano Ermon、Christopher D. Manning、Chelsea Finn，*Direct Preference Optimization: Your Language Model is Secretly a Reward Model*（NeurIPS 2023）：[arXiv](https://arxiv.org/abs/2305.18290)｜[PDF](https://arxiv.org/pdf/2305.18290)

> **论文 ID：** arXiv:2305.18290　 **论文名称：** Direct Preference Optimization: Your Language Model is Secretly a Reward Model　 **作者：** Rafael Rafailov、Archit Sharma、Eric Mitchell、Stefano Ermon、Christopher D. Manning、Chelsea Finn，2023　 **发布时间：** 2023 年 5 月 29 日（arXiv 首次提交）　 **原文：** [arXiv](https://arxiv.org/abs/2305.18290)｜[PDF](https://arxiv.org/pdf/2305.18290)

#### 核心观点

DPO（Direct Preference Optimization）回答了一个很实际的问题：**若已经有“chosen 比 rejected 更好”的偏好对，是否一定要先训练一个独立 Reward Model，再用 PPO 做强化学习？** 论文的答案是：不一定。DPO 把经典 RLHF 的“奖励建模 + RL”重参数化为对语言模型策略本身的一个分类式损失，直接学习偏好。

```text
经典 RLHF
SFT Model → Preference Data → Reward Model → PPO → Aligned Model

DPO
SFT Model + (prompt, chosen, rejected) → DPO loss → Aligned Model
```

##### 1. 改变的不是偏好数据，而是优化路径

RLHF 与 DPO 都需要人类（或其他来源）提供成对偏好：给定 prompt \(x\)，有被选中的回答 \(y_w\) 与被拒绝的回答 \(y_l\)。不同在于：

- **经典 RLHF：** 用偏好对训练显式 RM；再在采样—打分—PPO 的强化学习循环中优化 policy。
- **DPO：** 不单独保存或训练一个 RM，也不运行 PPO；直接让当前 policy 相对参考模型更偏向 \(y_w\)、更远离 \(y_l\)。

因此，DPO 不是“不需要人类偏好”，而是**不再需要把偏好先压缩成一个独立奖励网络、再通过在线 RL 最大化它**。

![Figure 1：经典 RLHF 与 DPO 的原始管线对比](C:\Users\will\Downloads\assets\arXiv-2305.18290-v2.0-figure-1.png)

*Figure 1（论文第 2 页）：左侧 RLHF 先用 preference data 训练 Reward Model，再反复采样、以奖励训练 LM policy；右侧 DPO 直接从 preference data 通过 maximum likelihood 优化最终 LM。来源：[论文 PDF，第 2 页](https://arxiv.org/pdf/2305.18290#page=2)。*

##### 2. “Language Model is secretly a Reward Model”是什么意思？

经典 KL 约束 RLHF 的最优策略与奖励存在解析关系。DPO 将这一关系反过来表示：策略 \(\pi_\theta\) 相对于参考策略 \(\pi_{ref}\) 的对数概率比，可以对应一个**隐式奖励**。在 Bradley–Terry 偏好模型下，分区函数会在成对差分中抵消，于是可直接写出策略损失：

$$
\mathcal{L}_{\mathrm{DPO}}
=-\mathbb{E}_{(x,y_w,y_l)}\left[\log\sigma\!\left(\beta\left(
\log\frac{\pi_\theta(y_w\mid x)}{\pi_{ref}(y_w\mid x)}
-\log\frac{\pi_\theta(y_l\mid x)}{\pi_{ref}(y_l\mid x)}
\right)\right)\right]
$$

直觉上，DPO 同时做两件事：提高 chosen 相对参考模型的概率，降低 rejected 相对参考模型的概率。\(\beta\) 控制偏好优化力度；\(\pi_{ref}\) 通常是冻结的 SFT 模型，起到“不要偏离原始能力分布太远”的锚点作用。

##### 3. 为什么 DPO 通常更易训练？

PPO-RLHF 需要维护独立 RM、从当前 policy 反复采样，并处理奖励尺度、KL 系数与 RL 稳定性等问题。DPO 则把训练变成离线 preference pairs 上的普通反向传播：没有 policy rollout 训练环，也不需要显式的奖励模型训练阶段。

这并不意味着 DPO 放弃了 RLHF 原本的对齐目标；论文将其表述为：在相同的偏好模型与 KL 约束视角下，直接优化与该隐式奖励相对应的最优 policy。

#### 带来的收益

- **训练管线更短：** `Preference Pairs → DPO → Policy` 取代 `Preference Pairs → RM → PPO → Policy`，显著减少工程组件与调参面。
- **计算与稳定性负担更低：** 论文强调 DPO 训练时不需要从 LM 进行在线采样，也避免了 PPO 式强化学习的复杂稳定性问题。
- **保留偏好对齐能力：** 论文在情感控制上优于 PPO-RLHF，并在摘要与单轮对话中匹配或改善回答质量；这些结论基于论文所用模型规模（最高 6B）和评测任务。
- **仍受数据与假设约束：** DPO 的质量上限由 chosen/rejected 偏好数据决定，仍需参考模型与超参数 \(\beta\)，并依赖偏好模型假设；它不是“无需奖励概念”或“无需对齐数据”。

一句话：**DPO 将“先学 Reward Model、再用 PPO 最大化奖励”的两阶段 RLHF，改写成对 chosen/rejected 偏好对的直接策略优化，让语言模型以隐式 Reward Model 的形式完成偏好学习。**


因此现代 Preference Alignment 更适合画成两条路线：

``` text
                  SFT
                   │
                   ▼
         Preference Alignment
             /           \
            ▼             ▼
      Classic RLHF       DPO
            │             │
      Reward Model   Preference Pairs
            │             │
           PPO            │
            └──────┬──────┘
                   ▼
              Aligned Model
```

### 1. Full Fine-tuning：全量微调 vs PEFT：参数高效微调

**Full Fine-tuning** 是最直接的模型适配方式：

``` text
Pre-trained Model
       ↓
Fine-tuning Dataset
       ↓
Forward → Loss → Backpropagation
       ↓
Update ALL Parameters
       ↓
Fine-tuned Model
```

即：**模型中的全部参数都参与梯度更新。**

随着模型规模增大，全量微调需要为大量参数维护 Model Weights、Gradients、Optimizer States，同时还要保存训练过程中的 Activations，因此训练成本快速增加。

------------------------------------------------------------------------

**PEFT：参数高效微调**

**PEFT = Parameter-Efficient Fine-Tuning**

随着预训练模型越来越大，一个直接的问题是：

> **为了适配一个新任务，是否真的需要重新训练整个模型的几十亿甚至几百亿参数？**

PEFT 的核心思想：

``` text
Full Fine-tuning

████████████████████████
      全部参数 Trainable


             ↓


PEFT

████████████████████████   Frozen
             ██            Trainable

      只训练少量参数
```

即：

> **冻结全部或绝大多数预训练模型参数，只训练少量新增参数或选定参数，从而以更低成本完成模型适配。**

#### 代表论文

**Parameter-Efficient Transfer Learning for NLP（2019）**

论文：https://arxiv.org/abs/1902.00751

该论文提出 Adapter Modules：保持原始预训练模型参数冻结，为不同任务加入少量可训练参数。在论文的 GLUE 实验中，每个任务新增约 3.6% 参数即可取得接近 Full Fine-tuning 的性能。

它可以作为课程中从 **Full Fine-tuning → Parameter-Efficient Transfer/Fine-Tuning** 思想演进的重要代表工作。

#### Adapter Modules：冻结骨干，用少量任务参数完成迁移

##### 来源

- Neil Houlsby、Andrei Giurgiu、Stanisław Jastrzębski、Bruna Morrone、Quentin de Laroussilhe、Andrea Gesmundo、Mona Attariyan、Sylvain Gelly，*Parameter-Efficient Transfer Learning for NLP*（ICML 2019）：[arXiv](https://arxiv.org/abs/1902.00751)｜[PDF](https://arxiv.org/pdf/1902.00751)

> **模型：** Adapter Modules for BERT　 **模型厂家：** Google Research　 **论文 ID：** arXiv:1902.00751　 **论文名称：** Parameter-Efficient Transfer Learning for NLP　 **作者：** Neil Houlsby、Andrei Giurgiu、Stanisław Jastrzębski、Bruna Morrone、Quentin de Laroussilhe、Andrea Gesmundo、Mona Attariyan、Sylvain Gelly，2019　 **发布时间：** 2019 年 2 月 2 日（arXiv 首次提交）　 **原文：** [arXiv](https://arxiv.org/abs/1902.00751)｜[PDF](https://arxiv.org/pdf/1902.00751)

##### 核心观点

这篇论文提出了今天 PEFT（Parameter-Efficient Fine-Tuning）最具代表性的早期方案之一：**保留同一份预训练模型骨干，为每个下游任务新增一小组 Adapter 参数；训练新任务时冻结原始主干，仅训练这些任务专属小模块。**

它要解决的不是“能否迁移”，而是“任务越来越多时，能否不为每个任务复制并保存一整份模型”。全量微调的代价是每个任务都要有一套完整权重；Adapter 的代价则近似为：

```text
共享：1 份冻结的预训练 Transformer / BERT
任务 A：Adapter A + 分类头
任务 B：Adapter B + 分类头
任务 C：Adapter C + 分类头
```

###### 1. Adapter 放在哪里？每个 Transformer 层放两次

论文在每个 Transformer layer 的两个子层后各插入一个 Adapter：

1. Multi-Head Attention 后的投影之后；
2. Feed-Forward Network 后的投影之后。

Adapter 位于子层输出与残差连接相加之前，之后再进入 LayerNorm。论文中训练的是 Adapter、任务专属 LayerNorm 参数以及最终分类层；预训练网络的其余原始权重保持冻结。

![Figure 2：Adapter 在 Transformer 中的位置与其瓶颈结构](C:\Users\will\Downloads\assets\arXiv-1902.00751-figure-2.png)

*Figure 2（论文第 3 页）：左图表示每层 Transformer 在 Attention 与 Feed-Forward 两个子层后各接入一个 Adapter；右图是 Adapter 内部的 bottleneck 与残差连接。绿色模块是下游任务训练时更新的部分。来源：[论文 PDF，第 3 页](https://arxiv.org/pdf/1902.00751#page=3)。*

###### 2. 为什么参数少：瓶颈（bottleneck）而非完整新层

若 Transformer 隐藏维度为 \(d\)，Adapter 先把表示降到很小的瓶颈维度 \(m\)，再升回 \(d\)：

$$
h \;\longrightarrow\; W_{\mathrm{down}}h \;(d\!\rightarrow\!m)
\;\longrightarrow\; \text{nonlinearity}
\;\longrightarrow\; W_{\mathrm{up}}(\cdot) \;(m\!\rightarrow\!d)
\;\longrightarrow\; h + \text{Adapter}(h)
$$

当 \(m \ll d\) 时，新增参数远小于全量层。论文给出的单个 bottleneck Adapter 参数量（含偏置）为 \(2md+d+m\)。\(m\) 因而成为性能与任务存储开销之间最直接的旋钮。

###### 3. 近恒等初始化：先不扰动，再逐步适配

Adapter 带有内部 skip connection，并将投影层初始化到接近零，使新模块在训练开始时近似恒等映射。这样，插入 Adapter 后的网络起点尽量保持原有预训练行为；训练再逐步学习任务所需的偏移。论文发现，若初始化偏离恒等映射过远，训练可能失败。

###### 4. 它与“冻结所有预训练参数”的关系

用户常将 Adapter 概括为“冻结原模型参数”，这个方向是对的，但原论文的精确实现有一处细节：除新增 Adapter 与任务头外，**LayerNorm 参数也按任务训练**。因此更准确的说法是：冻结预训练 Transformer 的主体权重，用小型任务专属组件承担适配。

##### 带来的收益

- **多任务存储大幅节省：** 同一骨干被所有任务共享，新增任务只保存少量 Adapter、LayerNorm 与任务头，而非复制整套 BERT。
- **性能接近全量微调：** 论文在 GLUE 上报告，Adapter 与全量微调的性能差距在 **0.4%** 以内，而每个任务仅增加 **3.6%** 参数；全量微调则需要为每个任务训练 100% 参数。
- **适合连续加入任务：** 新任务无需回访或修改旧任务的 Adapter；冻结共享主干使旧任务行为不会被新任务训练直接遗忘。
- **奠定 PEFT 的设计范式：** “冻结大骨干 + 训练小型可插拔模块”使参数高效微调成为现实工程选择。不过，Adapter 会带来额外模块和推理路径；其性能也取决于瓶颈维度、插入位置与具体任务，并非在所有设置下都必然等同于全量微调。

一句话：**Adapter Modules 将任务适配从“复制并改写整个预训练模型”改成“共享冻结骨干、为每个任务插入很小的可训练瓶颈”，以接近全量微调的效果换取数量级更低的任务增量参数。**

### 3. 聚焦 LoRA

#### 3.1 LoRA 要解决什么问题？

#### 代表论文

**LoRA: Low-Rank Adaptation of Large Language Models（2021）**

论文：https://arxiv.org/abs/2106.09685

##### LoRA：以低秩增量高效适配大语言模型

##### 来源

- Edward J. Hu、Yelong Shen、Phillip Wallis、Zeyuan Allen-Zhu、Yuanzhi Li、Shean Wang、Lu Wang、Weizhu Chen，*LoRA: Low-Rank Adaptation of Large Language Models*（2021）：[arXiv](https://arxiv.org/abs/2106.09685)｜[PDF](https://arxiv.org/pdf/2106.09685)

> **模型：** LoRA（Low-Rank Adaptation）　 **模型厂家：** Microsoft Corporation　 **论文 ID：** arXiv:2106.09685　 **论文名称：** LoRA: Low-Rank Adaptation of Large Language Models　 **作者：** Edward J. Hu、Yelong Shen、Phillip Wallis、Zeyuan Allen-Zhu、Yuanzhi Li、Shean Wang、Lu Wang、Weizhu Chen，2021　 **发布时间：** 2021 年 6 月 17 日（arXiv 首次提交）　 **原文：** [arXiv](https://arxiv.org/abs/2106.09685)｜[PDF](https://arxiv.org/pdf/2106.09685)

##### 核心观点

LoRA 的核心判断是：**下游任务适配时，真正需要加到预训练权重上的更新 \(\Delta W\) 往往具有很低的内在秩。** 因而不必训练完整权重矩阵，只需训练两个很小的低秩矩阵来表示这次更新。

对冻结的预训练线性层 \(W_0\in\mathbb{R}^{d\times k}\)，LoRA 写作：

$$
W = W_0 + \Delta W = W_0 + BA,
\qquad B\in\mathbb{R}^{d\times r},\ A\in\mathbb{R}^{r\times k},\ r\ll\min(d,k)
$$

前向计算变为：

$$
h = W_0x + BAx
$$

其中 \(W_0\) 始终冻结，只有 \(A,B\) 可训练。原来要为 \(d\times k\) 矩阵训练 \(dk\) 个参数，现在只需约 \(r(d+k)\) 个参数。

###### 1. Figure 1：只训练 A 和 B，初始行为不变

论文将 \(A\) 随机高斯初始化、\(B\) 初始化为零，因此训练一开始 \(BA=0\)。这保证模型刚插入 LoRA 时与原预训练模型完全一致，之后再从零开始学习任务相关的低秩增量。

![Figure 1：LoRA 的低秩重参数化](C:\Users\will\Downloads\assets\arXiv-2106.09685-figure-1.png)

*Figure 1（论文第 1 页）：冻结的预训练权重 \(W\) 与可训练的低秩分解 \(BA\) 并行作用于同一输入；\(B=0\) 使初始增量为零，训练时只更新 \(A,B\)。来源：[论文 PDF，第 1 页](https://arxiv.org/pdf/2106.09685#page=1)。*

###### 2. LoRA 放在哪里？论文重点研究 Attention 投影

LoRA 原理可用于任意稠密层。论文在 Transformer 中重点研究 self-attention 的投影矩阵 \(W_q,W_k,W_v,W_o\)，并主要适配 attention 权重、冻结 MLP；这是一种在参数效率与效果之间的实用选择，而非 LoRA 的数学限制。

不同任务共享同一份 \(W_0\)，只需切换各自的 \(A,B\)。例如，一个基础模型可同时挂载“摘要 LoRA”“客服 LoRA”“代码 LoRA”等小增量，而无需保存多份完整基础模型。

###### 3. 为什么部署时没有额外推理延迟？

训练时可按 \(W_0x+BAx\) 计算；部署前可将增量合并：

$$
W_{\mathrm{merged}}=W_0+BA
$$

之后仍是一次普通矩阵乘法，没有像串行 Adapter Layer 那样新增网络深度。这是原论文强调 LoRA 适合延迟敏感部署的关键原因。若需要切换任务，可恢复 \(W_0\)，再合并另一组 \(B'A'\)。

###### 4. rank \(r\) 是效率与表达能力的旋钮

\(r\) 越小，训练参数、优化器状态和存储越少，但可表达的更新空间也越受限；\(r\) 增大则逐步接近全量更新的表达能力。论文在 GPT-3 175B 的实验设定中观察到，即使 \(d=12{,}288\)，非常低的 rank（如 \(r=1\) 或 \(2\)）也可能足够有效；这是一项实证发现，不能机械地推广为所有任务都应使用相同 rank。

##### 带来的收益

- **大幅降低可训练参数：** 论文以 GPT-3 175B + Adam 为例，报告 LoRA 可将可训练参数减少至多 **10,000 倍**；这减少了任务增量权重与优化器状态。
- **降低训练显存压力：** 冻结大部分权重意味着不必为它们维护梯度和 Adam 状态；论文报告 GPU 显存需求可降至原来的约三分之一。
- **多任务切换轻量：** 多个任务共享基础模型，只保存各自小型 \(A,B\)；适合多租户、领域适配和模型个性化场景。
- **合并后无额外推理路径：** 将 \(BA\) 合并回 \(W_0\) 后，推理结构与原模型相同。论文报告其在 RoBERTa、DeBERTa、GPT-2 与 GPT-3 上达到不弱于全量微调的质量，同时避免原始 Adapter 的额外推理延迟。
- **需要谨慎选择作用位置与 rank：** LoRA 不会自动保证所有任务都等同全量微调；目标层、\(r\)、缩放系数及数据规模都会影响结果，且同时叠加多个 LoRA 可能产生干扰。

一句话：**LoRA 用 \(\Delta W=BA\) 把“更新整个大矩阵”改成“训练一个低秩增量”，在冻结基础模型的前提下实现高效微调，并能在部署时合并回原权重而不增加推理延迟。**

#### 3.2 参数量示例：为什么 LoRA 能显著减少训练参数？

### 1. Megatron-LM：把巨大的 Transformer 拆开计算

#### 代表论文

**Megatron-LM: Training Multi-Billion Parameter Language Models Using Model Parallelism（2019）**

论文：https://arxiv.org/abs/1909.08053

#### Megatron-LM：用 Tensor Model Parallelism 训练十亿级 Transformer

##### 来源

- Mohammad Shoeybi、Mostofa Patwary、Raul Puri、Patrick LeGresley、Jared Casper、Bryan Catanzaro，*Megatron-LM: Training Multi-Billion Parameter Language Models Using Model Parallelism*（2019）：[arXiv](https://arxiv.org/abs/1909.08053)｜[PDF](https://arxiv.org/pdf/1909.08053)

> **模型：** Megatron-LM　 **模型厂家：** NVIDIA　 **论文 ID：** arXiv:1909.08053　 **论文名称：** Megatron-LM: Training Multi-Billion Parameter Language Models Using Model Parallelism　 **作者：** Mohammad Shoeybi、Mostofa Patwary、Raul Puri、Patrick LeGresley、Jared Casper、Bryan Catanzaro，2019　 **发布时间：** 2019 年 9 月 17 日（arXiv 首次提交）　 **原文：** [arXiv](https://arxiv.org/abs/1909.08053)｜[PDF](https://arxiv.org/pdf/1909.08053)

##### 核心观点

Megatron-LM 的关键贡献是提出一种贴合 Transformer 结构的**层内张量并行（intra-layer / tensor model parallelism）**：不把完整 Transformer layer 放到单张 GPU，而是把 layer 内的大矩阵按列或按行切分给多张 GPU，并把通信压缩到少数 all-reduce。

它解决的核心瓶颈是：数据并行只能复制完整模型；当模型权重、梯度、激活和 Adam 优化器状态已经装不进单卡时，必须先把**一个 layer 内部的参数与计算**切开。该方法可与数据并行叠加，也与 pipeline parallelism 正交。

###### 1. MLP：第一层列切，第二层行切

Transformer MLP 可抽象为：

$$
Y=\operatorname{GeLU}(XA),\qquad Z=YB
$$

Megatron-LM 将第一矩阵 \(A\) **按列切分**为 \([A_1,A_2]\)。每张 GPU 都拿到完整输入 \(X\)，独立计算 \(\operatorname{GeLU}(XA_i)\)，因此非线性 GeLU 前不必同步。随后把第二矩阵 \(B\) **按行切分**，让每张 GPU 直接消费对应的 \(Y_i\)，最后仅在输出处 all-reduce 求和。

关键在于切分方向顺着矩阵乘法与非线性排布：若在第一层行切，就必须在 GeLU 之前先聚合 \(X_1A_1+X_2A_2\)，会额外引入同步点。

###### 2. Attention：把 attention heads 分给不同 GPU

多头注意力天然可并行。论文将 \(Q,K,V\) 的投影按列切分，使每张 GPU 负责一部分 attention heads；各 head 的 attention、softmax 和局部输出都可以独立完成。输出投影再按行切分，并在末尾做一次 all-reduce。

![Figure 3：MLP 与 Self-Attention 的层内模型并行](C:\Users\will\Downloads\assets\arXiv-1909.08053-figure-3.png)

*Figure 3（论文第 4 页）：(a) MLP 的第一 GEMM 列并行、第二 GEMM 行并行；(b) 将 attention heads 以及 Q/K/V 投影分给不同 GPU。\(f\) 在前向是恒等、反向做 all-reduce；\(g\) 在前向做 all-reduce、反向是恒等。来源：[论文 PDF，第 4 页](https://arxiv.org/pdf/1909.08053#page=4)。*

###### 3. 通信如何被控制在“每层少数几次”

对一个 MLP block，输出处的 \(g\) 在前向 all-reduce，配对的 \(f\) 在反向 all-reduce；attention block 使用相同思路。因此一个 Transformer layer 的前向路径有两次 all-reduce（MLP 一次、attention 一次），反向也有两次。中间大多数 GEMM、GeLU、softmax 和局部 head 计算都保持在本地 GPU 内。

这是该方案的工程要点：不是简单把矩阵任意切开，而是选择让通信落在残差/输出聚合边界的切法，避免在非线性与注意力计算的中间频繁同步。

###### 4. 与数据并行、流水线并行的关系

- **Tensor/model parallel：** 多卡共同保存和计算同一层，解决“单层装不下”。
- **Data parallel：** 多个模型副本处理不同数据 batch，再聚合梯度，解决吞吐扩展。
- **Pipeline parallel：** 不同 GPU 放不同层，解决层间模型切分，但需要处理流水线气泡。

Megatron-LM 的张量并行可以在一个 model-parallel group 内使用，再由多个 group 做数据并行。论文的 8.3B 实验使用 512 张 GPU，其中采用 8 路模型并行并叠加 64 路数据并行。

##### 带来的收益

- **突破单卡显存上限：** 每张 GPU 只保存大矩阵与优化器状态的一部分，使十亿级 Transformer 的训练可行。
- **通信效率高：** 利用 MLP 与 attention 的结构，将每个 Transformer layer 的通信压缩到少数 all-reduce，而非为每次局部算子频繁同步。
- **可与其他并行维度组合：** 张量并行负责层内切分，数据并行负责吞吐，pipeline parallel 可进一步扩展模型深度与设备规模。
- **论文验证了实际扩展性：** 作者训练到 **8.3B** 参数 GPT-2 类模型与 **3.9B** 参数 BERT 类模型；在 **512 GPU** 上报告 **15.1 PFLOPs** 持续算力和相对强单卡基线 **76%** 的 scaling efficiency。
- **边界与代价：** 张量并行对 GPU 间高带宽、低延迟互连非常敏感；跨节点通信、并行度选择和与数据/流水线并行的组合会直接影响利用率。它解决的是训练系统规模问题，不替代数据、优化或模型架构层面的改进。

一句话：**Megatron-LM 通过“MLP 列切+行切、Attention 按 head 切”的结构化张量并行，让多张 GPU 像一张更大的 GPU 一样共同执行一个 Transformer layer，并将代价控制在少量 all-reduce 通信上。**

2019 年的 Megatron-LM 重点解决了 **Transformer Layer 内部如何进行 Tensor Parallelism**。当训练进一步扩展到更大的 GPU 集群时，仅有 TP 还不够，还需要把 Data Parallelism 与 Pipeline Parallelism 组合起来。

### 2. Megatron-LM：从 TP 到 3D Parallelism

                       Megatron-LM

```

可以用一句话记住：

> **DP 拆数据，TP 拆 Layer 内部计算，PP 按 Layer 拆模型。**

三者组合形成经典的：

```text

#### Megatron-LM 3D 并行：Tensor、Pipeline 与 Data Parallelism 的系统组合

##### 来源

- Deepak Narayanan、Mohammad Shoeybi、Jared Casper、Patrick LeGresley、Mostofa Patwary、Vijay Anand Korthikanti、Dmitri Vainbrand、Prethvi Kashinkunti、Julie Bernauer、Bryan Catanzaro、Amar Phanishayee、Matei Zaharia，*Efficient Large-Scale Language Model Training on GPU Clusters Using Megatron-LM*（SC 2021）：[arXiv](https://arxiv.org/abs/2104.04473)｜[PDF](https://arxiv.org/pdf/2104.04473)

> **模型：** Megatron-LM　 **模型厂家：** NVIDIA　 **论文 ID：** arXiv:2104.04473　 **论文名称：** Efficient Large-Scale Language Model Training on GPU Clusters Using Megatron-LM　 **作者：** Deepak Narayanan、Mohammad Shoeybi、Jared Casper、Patrick LeGresley 等，2021　 **发布时间：** 2021 年 4 月 9 日（arXiv 首次提交）　 **原文：** [arXiv](https://arxiv.org/abs/2104.04473)｜[PDF](https://arxiv.org/pdf/2104.04473)

##### 核心观点

这篇工作将早期 Megatron-LM 的层内 Tensor Parallel 扩展为可在 GPU 集群上部署的系统方案：**Tensor Parallel（TP）+ Pipeline Parallel（PP）+ Data Parallel（DP）**。论文称其为 PTD-P。

不是把三种并行机械相乘，而是按硬件拓扑分工：将高频、通信密集的 TP 尽量放在单台多 GPU 服务器的高速 NVLink 域内；将模型深度的切分交给跨服务器的 PP；最后用 DP 复制这一模型分片组来扩展数据吞吐。

```text
GPU cluster
├─ Data Parallel：多个模型分片副本处理不同数据
│  ├─ Pipeline stage 1（若干 Transformer layers）
│  │  └─ Tensor Parallel：同一层的矩阵/heads 切至多张本机 GPU
│  └─ Pipeline stage 2（后续 layers）
└─ ...
```

###### 1. 三种并行各自解决不同瓶颈

- **TP：** 把单层内大矩阵与 attention heads 分割到多卡，解决单层参数/激活装不下的问题；但它需要频繁 all-reduce，跨节点代价高。
- **PP：** 将连续 Transformer layers 分给不同 stage；微批（microbatch）在 stage 间流动，解决整个模型不能放进单机的问题；代价是 pipeline bubble。
- **DP：** 复制完整模型分片组、分发不同数据并聚合梯度，扩大吞吐；但受到全局 batch 与梯度通信制约。

###### 2. Figure 2：节点内 TP，节点间 PP

论文原图把一段 Transformer layers 分为两个 Pipeline MP partition；每个 pipeline stage 内部再分为两个 Tensor MP partition：

![Figure 2：Tensor Parallel 与 Pipeline Parallel 的组合](C:\Users\will\Downloads\assets\arXiv-2104.04473-figure-2.png)

*Figure 2（论文第 3 页）：绿色边框表示 pipeline model-parallel partition，将不同 Transformer layers 分配到不同 stage；蓝色虚线表示同一 layer 内的 tensor model-parallel partition。Data Parallel 在这种模型并行组的外层复制。来源：[论文 PDF，第 3 页](https://arxiv.org/pdf/2104.04473#page=3)。*

这个层次化映射背后的原则是：**让 TP 留在快互连内，避免它的 all-reduce 穿越慢速跨机网络；让 PP 承担跨机的激活传递。** 论文指出，当模型超过单个多 GPU 服务器容量时，直接扩大 TP 会导致跨服务器 all-reduce，并可能因 GEMM 变小而降低 GPU 利用率。

###### 3. Interleaved pipeline：用更小 bubble 换取更多调度复杂度

普通流水线在一批 microbatches 开始与结束时会有设备空闲的 bubble；为保持严格同步优化器语义，batch 结束需 pipeline flush。论文提出 interleaved 1F1B：每个设备持有多个不连续的 model chunks，交错执行 forward 与 backward，使 flush 更早完成、bubble 更小。

代价是 stage 间通信次数增加、调度更复杂；论文报告在可比内存占用下，interleaved schedule 可将吞吐提高 **10% 以上**。

###### 4. 配置不是固定公式，而是通信、算子效率与气泡的折中

并行度选择决定：矩阵乘法是否足够大、TP 通信是否停留在节点内、PP bubble 的大小、激活内存与 DP 梯度通信。microbatch size 也是重要旋钮：太小会降低算术效率，太大则提高内存或限制 pipeline 调度。论文强调，不佳的 TP/PP 组合即使拥有高带宽网络，也可能带来最高约 **2 倍** 的吞吐损失。

##### 带来的收益

- **将系统规模从十亿级推进到万亿级：** 论文展示了 1T 参数 GPT 模型在 **3072 张 A100 GPU** 上的训练迭代。
- **将并行策略映射到硬件拓扑：** TP 的密集通信优先节点内完成，PP 跨服务器扩展模型深度，DP 再扩展吞吐，避免“所有通信都走最慢链路”。
- **可量化的系统效率：** 论文报告总吞吐 **502 PFLOP/s**、每 GPU **163 TFLOP/s**，约为设备理论峰值的 **52%**（含通信、数据处理与优化）。
- **减少 pipeline 空闲：** Interleaved 1F1B 在论文设定中以相近内存占用带来 10% 以上吞吐提升。
- **重要边界：** 这不是自动并行策略搜索器；最佳 TP/PP/DP 与 microbatch 配置仍依赖模型形状、GPU 拓扑和网络带宽。规模越大，跨节点通信往往越成为决定性约束。

一句话：**这篇论文把 Megatron-LM 从“单层如何切到多卡”推进为“整座 GPU 集群如何分层协作”：节点内 Tensor Parallel、节点间 Pipeline Parallel、外层 Data Parallel，并用 interleaved 调度减少流水线气泡。**

> 到这里可以用一句话记住经典 3D Parallelism：**DP 拆数据，TP 拆 Layer 内部计算，PP 按 Layer 拆模型。**

### 3. Megatron Core：现代多维并行

随着 Long Context 与 MoE 成为现代 LLM 的重要方向，Megatron Core 又扩展出更多并行维度：

```text
                      Megatron Core
                           │
       ┌─────────┬─────────┼─────────┬─────────┐
       ▼         ▼         ▼         ▼         ▼
      DP        TP        PP        CP        EP
       │         │         │         │         │
     Data      Tensor   Pipeline   Context   Expert
       │         │         │         │         │
     拆数据     拆层内      拆层      拆序列     拆专家
```

- **CP（Context Parallelism）**：沿序列维度拆分，面向长上下文训练。
- **EP（Expert Parallelism）**：把不同 Expert 分布到不同 GPU，面向 MoE 模型。

因此可以先建立一个简化认知：

```text
Dense LLM
   ↓
DP + TP + PP

Long-context LLM
   ↓
DP + TP + PP + CP

MoE LLM
   ↓
DP + TP + PP + EP
```

> **系统：** Megatron Core　 **开发机构：** NVIDIA　 **主题：** 大语言模型分布式训练并行体系　 **原文：** [Megatron Core 文档](https://docs.nvidia.com/megatron-core/)

##### 核心观点

Megatron-LM 早期的核心是 **3D 并行**：Tensor Parallel（TP）、Pipeline Parallel（PP）和 Data Parallel（DP）。Megatron Core 在此基础上面向两个新瓶颈继续扩展：

- **Long Context：** 序列长度增长使激活显存与 Attention 计算/通信急剧上升；
- **MoE：** 专家数量和 token 路由使参数放置、all-to-all 通信与专家计算效率成为新问题。

因此，现代训练配置不再只问“模型有多大”，还要问“序列有多长、是否使用 MoE、GPU 拓扑如何”。

```text
DP   切 Batch / 数据副本
PP   切模型深度 / Transformer layers
TP   切层内矩阵与 Attention heads
SP   切部分序列激活（通常配合 TP）
CP   切完整长序列与激活
EP   切 MoE experts
ETP  切单个 expert 内部的大矩阵
```

###### 1. 基础 3D 并行：DP、TP、PP

| 维度 | 切分对象                  | 主要解决的问题         | 主要代价                         |
| ---- | ------------------------- | ---------------------- | -------------------------------- |
| DP   | Batch                     | 扩大吞吐               | 梯度同步、模型状态复制           |
| TP   | 单层矩阵、Attention heads | 单层过大、隐藏维度过大 | 高频层内通信                     |
| PP   | 模型深度 / layers         | 整体模型放不下单机     | microbatch 调度、pipeline bubble |

典型思路是把 TP 置于节点内高速互连域，因为它频繁通信；把 PP 用于跨节点的层级切分；再在多个相同的 TP×PP 模型分片组外层使用 DP。

总 GPU 数可抽象为：

$$
\text{World Size}=DP\times PP\times TP
$$

###### 2. Sequence Parallel（SP）：为 TP 分担激活显存

SP 沿 sequence dimension 切分部分激活，尤其是 LayerNorm 与 Dropout 等不需要 token 间交互的模块。它通常与 TP 联用，以避免这些激活在每一个 TP rank 上重复保存。

SP 不等于完整的长上下文并行：它主要减小某些激活的复制，而没有将 Attention 所需的整段上下文完全分布出去。Megatron Core 的并行指南建议在使用 TP 时启用 SP。

###### 3. Context Parallel（CP）：为 Long Context 切完整序列

CP 将输入和所有激活按 sequence length 分到不同 GPU。对于 Linear、LayerNorm 等逐 token 运算，各卡只处理自己持有的 token；但 Attention 需要每个 query 与整段上下文的 KV 交互，因此必须在 attention 边界执行必要的通信。

```text
序列 tokens: [t₁ ... tₙ]
CP rank 0:   [t₁ ... tₙ/2]
CP rank 1:   [tₙ/2+1 ... tₙ]

本地：Linear / LayerNorm 等逐 token 运算
协同：Attention 的 Q 需访问全序列 KV
```

CP 的直接收益是每卡激活显存约按 CP 度数缩小，并可减少长序列下完全 activation recomputation 的需求。它可与 TP、PP、DP 组合：

$$
\text{World Size}=DP\times PP\times TP\times CP
$$

![NVIDIA Megatron Core：TP2CP2 的 Transformer layer 与通信模式](C:\Users\will\Downloads\assets\CP_overview.png)

*官方 Figure 1：一个同时使用 TP=2、CP=2 的 Transformer layer。Attention 邻近的通信属于 CP；其他块周围的通信属于 TP。CP 让各卡只保留一段序列的 KV，并在 Attention 中以 ring 式点对点通信完成必要的信息交换。来源：[NVIDIA Context Parallelism 文档](https://docs.nvidia.com/megatron-core/developer-guide/latest/user-guide/features/context_parallel.html)。*

![NVIDIA Megatron Core：TP 与 CP 组合相对于完全重计算的加速](C:\Users\will\Downloads\assets\CP_results.png)

*官方 Figure 2：175B GPT 在不同 TP×CP 配置下，相对完全 activation recomputation（TP8CP1）的速度提升。它说明 CP 不只是为避免 OOM，也可通过减少重计算并平衡计算与通信改善长上下文训练效率。来源：[NVIDIA Context Parallelism 文档](https://docs.nvidia.com/megatron-core/developer-guide/latest/user-guide/features/context_parallel.html)。*

注意 SP 与 CP 的职责不同：**SP 分摊部分序列激活，CP 分片完整上下文和全部激活。**

###### 4. Expert Parallel（EP）：为 MoE 按专家切分

MoE 层并不是每个 token 都经过同一个 FFN，而是 router 为 token 选择少数 experts。EP 将 experts 放到不同 GPU：本卡得到 token 后，按 router 决策把 token 派发到承载相应 expert 的 GPU，专家计算结束后再把结果返回并合并。

```text
tokens → Router → token dispatch / all-to-all → Expert GPUs → combine
```

EP 的目标是让每卡只存一部分专家权重，并尽量使每个 expert 的 GEMM 足够大。当前 Megatron Core 文档特别指出：对专家层，EP 往往优于用高 TP 度数硬切 expert，因为高 TP 会让单 expert 的局部矩阵太小、通信相对更重。

###### 5. Expert Tensor Parallel（ETP）：再切过大的单个专家

若一个 expert 本身仍然太大，或需要在 expert 内继续分摊矩阵/显存，可使用 ETP。它是 MoE expert 内部的 Tensor Parallel，不应与密集 Attention 层的 TP 概念混为一谈。

一个实用的 MoE 并行视图是：

$$
\text{MoE expert group}=EP\times ETP
$$

其中 EP 决定“哪个 GPU 存哪几个 experts”，ETP 决定“一个 expert 内的大矩阵怎样拆”。对于细粒度 MoE，官方文档建议 ETP 通常设为 1，优先用 EP 保持更大的本地 expert GEMM。

###### 6. MoE Parallel Folding：Attention 与 MoE 使用不同并行网格

现代 MoE 的关键洞见是：**Attention 与 expert FFN 的最佳并行配置并不相同。**

| 部分        | 更自然的并行诉求                  |
| ----------- | --------------------------------- |
| Attention   | TP/CP 有助于大隐藏维度与长上下文  |
| MoE experts | EP 有助于按专家分布；必要时加 ETP |

Megatron Core 的 MoE Parallel Folding 将两类层的并行维度解耦：Attention 使用 `TP × CP × DP × PP`，MoE 使用 `ETP × EP × EDP × PP`。这样不会因 Attention 需要较高 TP 或 CP，就把同样的配置强行施加给专家层。

###### 7. 选择顺序：先少后多，优先降低通信

推荐的思考顺序是：

1. 先用 DP 扩吞吐；
2. 单层不适配显存时引入 TP，并尽可能放在节点内；
3. 模型深度或总状态超出单机时引入 PP；
4. 长上下文引入 CP，而不是仅盲目增大 TP；
5. MoE 引入 EP；只有单 expert 仍然太大时再引入 ETP；
6. 配合 Distributed Optimizer 或 Megatron-FSDP 分片模型状态，尽量把并行度留给 DP。

总原则是：**在不 OOM 的前提下，最小化模型并行度、最大化数据并行度。** 模型并行会增加通信和同步；DP 通常更容易带来吞吐扩展。

##### 带来的收益

- **长上下文可训练：** CP 直接沿 sequence length 分片，降低每卡激活显存，避免仅靠 activation recomputation 带来的显著额外计算。
- **MoE 可以随专家数扩展：** EP 将专家权重和计算分布到更多 GPU，使稀疏参数规模增长不必等比例复制到每卡。
- **避免错误的“一刀切”并行：** MoE Parallel Folding 允许 Attention 与 expert FFN 采用各自适合的并行网格。
- **形成可组合的训练坐标系：** 对密集长上下文模型，可考虑 `DP×PP×TP×CP`；对 MoE，还需加入 `EP×ETP`，并按硬件拓扑安排通信密度。
- **边界：** 并行维度越多，通信组、负载均衡、microbatch、路由 token 分布和 checkpoint 复杂度也越高。不存在对所有模型与集群都最优的一组固定并行度，必须用 profiling 验证。

### 4. DeepSpeed：训练状态怎么拆、显存怎么省？

如果课程上用 Megatron-LM 回答：

> **模型计算怎么拆？**

那么 DeepSpeed 最值得聚焦的问题就是：

> **Parameter、Gradient、Optimizer State 占用大量显存，怎么减少冗余？**

DeepSpeed：https://www.deepspeed.ai/

其最具代表性的技术是 **ZeRO**。

#### 代表论文

**ZeRO: Memory Optimizations Toward Training Trillion Parameter Models（2020）**

论文：https://arxiv.org/abs/1910.02054

#### ZeRO：通过消除数据并行冗余内存训练万亿参数模型

##### 来源

- Samyam Rajbhandari、Jeff Rasley、Olatunji Ruwase、Yuxiong He，*ZeRO: Memory Optimizations Toward Training Trillion Parameter Models*（2020）：[arXiv](https://arxiv.org/abs/1910.02054)｜[PDF](https://arxiv.org/pdf/1910.02054)

> **系统：** ZeRO（Zero Redundancy Optimizer）　 **开发机构：** Microsoft　 **论文 ID：** arXiv:1910.02054　 **论文名称：** ZeRO: Memory Optimizations Toward Training Trillion Parameter Models　 **作者：** Samyam Rajbhandari、Jeff Rasley、Olatunji Ruwase、Yuxiong He，2020　 **发布时间：** 2019 年 10 月 4 日（arXiv v1 首次提交；后续版本修订）　 **原文：** [arXiv](https://arxiv.org/abs/1910.02054)｜[PDF](https://arxiv.org/pdf/1910.02054)

##### 核心观点

ZeRO 的出发点是：传统数据并行（DDP）让每张 GPU 都保存**完整且重复**的模型状态。对于 Adam 混合精度训练，显存不只包含参数，还包括梯度、FP32 参数副本和一、二阶优化器状态；真正的瓶颈往往是这些重复状态，而非单纯的前向计算。

ZeRO（Zero Redundancy Optimizer）不改变数据并行的计算粒度，而是把数据并行组内冗余的模型状态分片保存：每个 rank 只常驻自己负责的一份，在需要时通过通信临时获得所需数据。目标是同时保留 DP 的高计算效率与模型并行的内存效率。

###### 1. ZeRO 三阶段：依次切优化器、梯度、参数

设模型参数量为 \(\Psi\)，数据并行度为 \(N_d\)。ZeRO-DP 的三个阶段可累积启用：

| 阶段                          | 分片对象                                  | 核心效果                                                     |
| ----------------------------- | ----------------------------------------- | ------------------------------------------------------------ |
| ZeRO Stage 1 / \(P_{os}\)     | Optimizer states                          | 优化器状态不再在各 rank 重复，论文报告约 4× 模型状态显存节省 |
| ZeRO Stage 2 / \(P_{os+g}\)   | Optimizer states + Gradients              | 梯度也分片，论文报告约 8× 节省                               |
| ZeRO Stage 3 / \(P_{os+g+p}\) | Optimizer states + Gradients + Parameters | 参数也分片，模型状态显存随 \(N_d\) 近似线性下降              |

![Figure 1：ZeRO 三阶段的每卡模型状态内存](C:\Users\will\Downloads\assets\arXiv-1910.02054-figure-1.png)

*Figure 1（论文第 3 页）：蓝色是 parameters、橙色是 gradients、绿色是 optimizer states。相对 Baseline，\(P_{os}\)、\(P_{os+g}\)、\(P_{os+g+p}\) 逐步消除三类状态在 DP ranks 间的复制。图中例子取 \(\Psi=7.5B\)、\(N_d=64\)、混合精度 Adam 的 \(K=12\)，每卡模型状态由 120GB 依次降至 31.4GB、16.6GB、1.9GB。来源：[论文 PDF，第 3 页](https://arxiv.org/pdf/1910.02054#page=3)。*

###### 2. 为什么 Stage 3 最关键？

Stage 1 和 2 虽然移除了昂贵的 optimizer/gradient 副本，但每张卡仍完整保存参数。Stage 3 连参数也分片，因此模型状态的每卡占用近似为：

$$
\frac{(2+2+K)\Psi}{N_d}
$$

其中 \(K\) 表示优化器状态的内存倍率。也就是说，当 DP 度数翻倍，Stage 3 的每卡模型状态近似减半；集群的聚合显存因此可以真正用于同一个更大的模型。

Stage 3 的代价是参数按需 all-gather、使用后再释放，论文分析其通信量相较纯 DP 约增加 50%。但这通常比跨节点高频 Tensor Parallel 更容易扩展，尤其当模型状态才是首要显存瓶颈时。

###### 3. ZeRO-DP 与 ZeRO-R：模型状态之外还要处理残余状态

ZeRO-DP 针对 parameters、gradients、optimizer states；当它们被分片后，激活、临时 buffer 和显存碎片会成为新的瓶颈。论文将这些剩余部分称为 residual states，并提出 ZeRO-R：

- 对 activation，减少复制、使用 activation partitioning，并在合适时 offload；
- 对 temporary buffer，控制 buffer 大小以平衡内存与计算；
- 对 fragmentation，按 tensor 生命周期主动管理内存。

因此，“ZeRO”在原论文中是 **ZeRO-DP + ZeRO-R** 的整体内存优化体系；今天常说的 ZeRO-1/2/3 则主要指 ZeRO-DP 的三种模型状态分片深度。

###### 4. 它与 Tensor/Pipeline Parallel 的关系

ZeRO 并不是 Tensor Parallel 或 Pipeline Parallel 的替代品：

- 若主要问题是参数、梯度和优化器状态重复，ZeRO 能用 DP 分片解决；
- 若单层矩阵、activation 或模型深度本身仍超出单卡/单机能力，仍可结合 TP、PP；
- 论文给出理论组合：DP 度数 \(N_d\) 与模型并行度 \(N_m\) 可带来最多约 \(N_d\times N_m\) 的每卡模型状态内存缩减。

##### 带来的收益

- **消除 DDP 的冗余模型状态：** 让数据并行不再意味着每卡必须保存完整 optimizer、gradient 与 parameter 副本。
- **显著扩大可训练模型：** 论文报告 ZeRO 在 400 GPU 上训练超过 100B 参数模型，实现 15 PFLOP/s；并分析 Stage 3 在当时硬件上具有训练万亿参数模型的内存潜力。
- **减少对模型重构的依赖：** 论文展示仅用 ZeRO 可训练最高约 13B 参数模型，而无需用户手写模型并行；这降低了大模型训练系统的使用门槛。
- **可与模型并行互补：** 当模型进一步变大或 activation 仍是瓶颈时，可将 ZeRO 与 TP/PP 组合，而不是在两者之间二选一。
- **边界：** 分片不会让显存问题凭空消失；Stage 3 带来按需参数通信，长序列仍可能受 activation 主导，实际效率依赖网络带宽、通信重叠、batch 与模型结构。

一句话：**ZeRO 把传统数据并行中“每卡重复保存完整训练状态”改为“不同 rank 分片保存、按需通信”，以尽量少牺牲 DP 计算效率的方式释放集群的聚合显存。**

传统 Data Parallel 中：

```text
GPU 0                 GPU 1                 GPU 2

Parameters            Parameters            Parameters
Gradients             Gradients             Gradients
Optimizer             Optimizer             Optimizer
States                States                States

   完整一份              完整一份              完整一份
```

多张 GPU 存在大量重复训练状态。

ZeRO 的核心思想：

> **不让每张 GPU 永久保存完整训练状态，而是把这些状态分片到不同 GPU。**

```text
              Training States
                    │
       ┌────────────┼────────────┐
       ▼            ▼            ▼
     GPU 0        GPU 1        GPU 2

> ZeRO 的三个阶段可以简记为：**Stage 1 分片 Optimizer States，Stage 2 再分片 Gradients，Stage 3 再分片 Parameters。** 分片越彻底，单卡显存占用越低，同时通信与系统实现也更复杂。

## 最终总结：大模型训练的三条技术主线

```text
                              大模型训练
                                  │
          ┌───────────────────────┼────────────────────────┐
          ▼                       ▼                        ▼
 ① 模型怎么训练出来？      ② 模型怎么高效微调？       ③ 大模型怎么训得动？
   Training Pipeline          Fine-tuning           Training Framework
          │                       │                        │
          ▼                       ▼                 ┌──────┴──────┐
    Pre-training          Full Fine-tuning          ▼             ▼
          │                       │            Megatron-LM     DeepSpeed
          ▼                       ▼                 │             │
     Base Model                  PEFT          TP / PP / DP      ZeRO
          │                       │             CP / EP       Stage 1/2/3
          ▼                       ▼
         SFT               常见 PEFT 方法
          │                       │
          ▼                       ▼
 Preference Alignment           LoRA
      /          \
     ▼            ▼
 RLHF / PPO      DPO
```

| 主线 | 核心问题 | 重点技术 |
|---|---|---|
| **Training Pipeline** | 模型能力是怎么训练出来的？ | Pre-training、SFT、RLHF/PPO、DPO |
| **Fine-tuning** | 已有模型怎么低成本适配？ | Full Fine-tuning、PEFT、LoRA |
| **Training Framework** | 超大模型如何在 GPU 集群上训得动？ | Megatron-LM、DeepSpeed、TP/PP/DP、ZeRO |

最终可以记住：

> **第一条：Pre-training → SFT → Preference Alignment，解决“模型怎么学会能力”。**

> **第二条：Full Fine-tuning → PEFT → LoRA，解决“微调时怎么少更新参数”。**

> **第三条：Megatron-LM + DeepSpeed，解决“超大模型怎么拆到 GPU 集群上训练”。**
